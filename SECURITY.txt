│  FOLLOWED SECURITY PRINCIPLES                                               │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  ✅ 1. Principle of Least Privilege                                        │
│        - Each admin has minimum required access                            │
│        - Department admins see only their emergencies                      │
│                                                                             │
│  ✅ 2. Defense in Depth                                                     │
│        - Multiple validation layers                                         │
│        - Authentication + Authorization                                     │
│        - Rate limiting + Session management                                 │
│                                                                             │
│  ✅ 3. Secure by Default                                                    │
│        - No default admin accounts (credentials required)                  │
│        - Session timeout enabled                                            │
│        - OTP required for user login                                        │
│                                                                             │
│  ✅ 4. Complete Mediation                                                   │
│        - Every request checked for authorization                            │
│        - Department filters applied to all queries                          │
│                                                                             │
│  ✅ 5. Open Design                                                          │
│        - Security through transparency                                      │
│        - No security by obscurity                                           │
│                                                                             │
│  ✅ 6. Separation of Duties                                                 │
│        - Different admins for different departments                         │
│        - Grand Admin has separate role                                      │
│                                                                             │
│  ✅ 7. Least Common Mechanism                                               │
│        - Separate authentication for users and admins                       │
│        - Different session storage                                         │
│                                                                             │
│  ✅ 8. Psychological Acceptability                                          │
│        - Security measures are user-friendly                                │
│        - Clear error messages                                               │
│        - Cooldown timer displayed                                           │

================================================================================
                          16. OTP SECURITY DETAILS
================================================================================

┌─────────────────────────────────────────────────────────────────────────────┐
│  OTP (ONE-TIME PASSWORD) IMPLEMENTATION                                     │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                             │
│  Generation: 6-digit random number (100000 - 999999)                       │
│  Validity: 5 minutes (300,000 milliseconds)                                │
│  Storage: Temporary (deleted after verification)                           │
│                                                                             │
│  Storage Keys:                                                              │
│  ├── otp_{phone} - Stores OTP code                                         │
│  └── otp_time_{phone} - Stores timestamp                                    │
│                                                                             │
│  Verification Process:                                                      │
│  ┌─────────────────────────────────────────────────────────────────────┐   │
│  │ 1. Check if OTP exists for phone                                    │   │
│  │ 2. Check if OTP is still valid (5 min expiry)                       │   │
│  │ 3. Compare entered OTP with stored OTP                              │   │
│  │ 4. Delete OTP after successful verification                         │   │
│  └─────────────────────────────────────────────────────────────────────┘   │
│                                                                             │
│  Security Notes:                                                            │
│  ├── OTP cannot be reused                                                  │
│  ├── Expired OTP automatically invalid                                     │
│  └── Demo mode shows OTP on screen (for testing)                           │
│                                                                             │
└─────────────────────────────────────────────────────────────────────────────┘
